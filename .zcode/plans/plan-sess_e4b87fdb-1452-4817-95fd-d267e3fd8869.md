# Étape 4 · 1/2 — Route récit, fiche & scrollytelling synchronisé

L'Étape 3 (lecteur audio multilingue) est livrée et commitée (`99fef20`). Le code est déjà pensé pour l'Étape 4 : `triggers.ts` modélise `visual:image` / `canvas:effect` / `audio:ambient` et le corpus les scripte (8 illustrations nommées avec traitement, 8 effets, 7 boucles), `Map3DHandle` se pilote de l'extérieur, `audio-timeline.ts` est réutilisable. Décisions prises avec l'utilisateur : **découpage en 2 moitiés** (comme l'Étape 3) et **route dédiée** `/recits/[id]` (URL partageable, retour navigateur, carte sticky embarquée).

Cette moitié 1/2 livre : la page récit (fiche + scrollytelling), la synchronisation **audio ↔ scroll ↔ caméra**, et les **11 illustrations SVG générées**. La moitié 2/2 (moteur canvas 8 effets, boucles d'ambiance, repli 2D carte) viendra ensuite.

## Plan

### 1. Route `/recits/[id]` — `src/app/recits/[id]/page.tsx` (nouveau)

Server Component suivant le patron de `page.tsx` :
- `generateStaticParams()` sur les ids du corpus ; `getStoryById(id)` (src/data/stories.ts) ; `notFound()` si inconnu.
- Next 15 : `params` est une **Promise** → `await params`.
- `generateMetadata` par récit (title = `story.title.fr`, description = `subtitle.fr`).
- Rendu `<StoryExperience story={story} />`.

### 2. `src/components/StoryExperience.tsx` (nouveau, client) — le cœur

**Propriétaire unique du moteur audio** : `const audio = useMultilingualAudio({ story })` (le cache module-level de Howls impose UNE instance par récit).

Layout (grille 2 colonnes desktop, empilée mobile) :
- **Colonne scrollable** :
  - *Hero fiche* : cover SVG (`story.cover.image`), titre, sous-titre, eyebrow catégorie + ère, région/département, peuples, langues disponibles — couleurs pilotées par `story.cover.palette` (prévu par le type `StoryCover`).
  - *Panneaux de chapitres* (16 au total sur le corpus) : illustration du trigger `visual:image` du chapitre (avec son `treatment` : ken-burns / parallax / fade en CSS), `chapter.narration.fr`, titre, timecodes.
  - *Pied de fiche* : crédits `story.credits` (sources, collecte, licence).
- **Colonne sticky** : `<Map3D ref>` + lecteur compact. La carte vole via `mapRef.current?.flyToStory(cameraViewFromChapter(story, index))` (helpers existants `src/components/Map3D.tsx:205-234`).

**Synchronisation (la boucle scrollytelling)** :
- *scroll → audio* : `IntersectionObserver` sur les panneaux ; quand un panneau devient majoritairement visible ET diffère du chapitre audio actif → `audio.goToChapter(index)`.
- *audio → scroll* : `useEffect` sur `audio.activeChapterIndex` ; si lecture en cours → `scrollIntoView({ behavior: 'smooth' })` du panneau, **supprimé pendant ~800 ms après un scroll utilisateur** (détection `wheel/touchmove`) pour ne jamais lutter avec l'utilisateur.
- *chapitre → caméra* : vol vers `cameraViewFromChapter` à chaque changement de chapitre actif (déjà la sémantique d'`onChapterChange` dans l'atlas).
- Sous-titre live `audio.activeSubtitle` affiché en bandeau sur la carte sticky (reuse de la logique de rendu de StoryPlayerCard).
- `prefers-reduced-motion` respecté (pas d'auto-scroll ni ken-burns).

### 3. Refactor léger de `StoryPlayerCard.tsx` — injection du moteur

Nouvelle prop **optionnelle** `audio?: MultilingualAudio` : si fournie, le composant l'utilise au lieu d'appeler le hook (injection de dépendance). L'atlas (sans la prop) garde son comportement actuel inchangé ; la page récit passe son instance unique. Ajout d'un lien « Ouvrir le récit ↗ » vers `/recits/[story.id]` quand un récit est sélectionné dans l'atlas (entrée n°1 vers le mode récit).

### 4. `scripts/generate-illustrations.mjs` (nouveau) + npm run assets:images

Génération des **11 SVG** (3 covers + 8 illustrations de chapitre) vers `public/images/stories/<story-id>/`, style géométrique « ethno-futuriste » **génératif et déterministe** (PRNG semé par story-id, comme les waveforms et l'audio démo — cohérent avec la philosophie placeholder du projet) : compositions de formes (arcs, losanges, motifs tessellés) colorées par la `palette` du récit lue dans stories.json. Motifs distincts par nom d'illustration (guerrière → silhouette cavalière abstraite, remparts → rangées de pierres, etc. — interprétation libre mais différenciée).

**Fix de nommage** : `stories.json` référence `/images/stories/yennenga/…` alors que la convention (README + autres récits) est `<story-id>` complet → aligner les chemins Yennenga sur `yennenga-mere-des-moose/` (les fichiers n'existant pas encore, aucun lien cassé).
